# Sequoia menu — audit, 23 Nov 2026

Scope: customer menu (`index.html`, `assets/*`), Sequoia API (`apps/loyalty`), captain screen, Caddy/droplet setup (`tools/*`), live site `sequoia.menu.titan22agency.com`. Payroll is noted only where it shares the server.
Method: code read, git history scan, live HTTP checks (headers, hidden paths, one harmless invalid API call), byte measurements in a browser and with curl.

## Security (most severe first)

| # | Severity | Finding | Evidence | Fix |
|---|---|---|---|---|
| S1 | **High** | Unsigned table links still accepted live (`TABLE_QR_LEGACY=1`). Anyone can send fake "Ready to order" / bill calls for any table from anywhere. Limits: 20 per table per 10 min, 40 per IP per hour; changing IP gets around them. | Live `POST /api/calls` with table 99 and no signature passed the table check (stopped only by the invalid type I sent; no call was created). | Print signed QRs (`node apps/loyalty/server.js table-links https://sequoia.menu.titan22agency.com/ 1 30`), put them on the tables, then set `TABLE_QR_LEGACY=0` and restart. |
| S2 | Medium | Backups stay on the same droplet (daily copy, 7 kept). A lost droplet loses the database and its backups. Restore never tested. | `tools/loyalty-setup.sh` backup script | Copy the nightly backup off the server (DigitalOcean Spaces or droplet backups) and run one test restore. |
| S3 | Medium | Staff login: per-IP limit only (10 per 15 min), no per-account lockout, no 2FA. | `server.js` `/staff/login` | Per-account lockout; optional owner 2FA. Needed before the admin panel can change prices. |
| S4 | Medium | No real roles: `admin` and `captain` can do the same things. | `server.js`: no route checks `role` | Owner / manager / staff roles checked on the server (part of the admin panel). |
| S5 | Medium | Repo is public: server code, setup scripts, captain page address and report-sheet URL are visible. No secrets found in the full git history. Logins and tokens still protect everything. | GitHub API 200; history scan | Make the repo private and give the droplet a read-only deploy key. Owner decision. |
| S6 | Medium | Payroll site (same server) sends no CSP header, and stores session tokens unhashed. | Live headers; `apps/payroll/server.js` | Same header block as the menu; hash tokens like the menu API does. |
| S7 | Low | Captain screen puts `kind` from a staff "undo" message into HTML without escaping. Staff-only, and CSP blocks inline script. | `assets/captain.js:131` | Allow only `call`/`bill`/`req`. |
| S8 | Low | A password reset does not end the user's open sessions. | `setStaff` | Delete that user's sessions on reset. |
| S9 | Low | Rate limits are in memory (reset on restart). Live streams (SSE) have no per-user cap. | `limiter()`, `stream()` | Cap streams per session. |
| S10 | Low | `GET /api/me?table=` changes data (seat presence) on a GET. | `server.js` `/me` | Move to POST. |
| S11 | Low | `Sequoia-Menu.zip` in the repo (old images only, checked). Live returns 404. Makes the secrets check fail every time. | `unzip -l` | Delete it from the repo. |

Already good, kept: scrypt password hashes; hashed session tokens; HttpOnly + Secure + SameSite cookies; CSRF header + Origin check; parameterised SQL everywhere; OTP HMAC with attempt limits; signed + time-checked webhook; body size limits; API bound to 127.0.0.1 behind Caddy; live HSTS, CSP (`script-src 'self'`), nosniff, frame deny; `.git`, `tools`, `apps`, `*.zip` return 404 live (checked).

Not applicable yet: image uploads, menu editing. These arrive with the admin panel and get their own review.

## Performance (measured 23 Nov, before any change)

| What | Now |
|---|---|
| HTML | 7.9 KB (zstd on) |
| Our JS (5 files) | 24 KB transferred |
| Our images on first screen | 200 KB (texture 98 KB, Walkman mascot 90 KB) |
| Google Fonts | 1 CSS + up to 45 font files from 2 other origins; Latin set 230 KB, Arabic 135 KB more when switched |
| First visit total | ≈ 460 KB (233 KB ours + ≈ 230 KB fonts) |
| Server response (TTFB) from this PC | 0.26–0.29 s |
| Offline / weak Wi-Fi | No service worker: no menu without a connection |
| Layout shift (CLS) | 0 |

Estimate, not measured: on slow 4G (1.6 Mbit/s, 150 ms) 460 KB plus 3 origins ≈ 3 s. Target is under 2 s. LCP could not be measured (browser pane was hidden); a phone-profile Lighthouse run comes first in the performance step.

Planned fixes, each measured before/after:
1. Self-host and subset the fonts, drop unused weights (est. 230 → ≈ 80 KB, removes 2 origins and the render-blocking CSS).
2. Resize the mascots to 2× their shown size (shown at 184 px, file is 700 px wide).
3. Service worker that keeps the last menu for weak Wi-Fi.
4. Versioned file names for JS so they can be cached long-term instead of revalidated every visit.
